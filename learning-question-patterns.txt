하데스 보카 학습 문제 풀이 패턴 정리
====================================

문서 목적
- 단어학습과 실전회화가 어떤 방식으로 문제를 출제하고 렌더링하는지 정리한다.
- 앞으로 문제를 추가할 때 데이터 의도와 UI 책임을 헷갈리지 않게 한다.


1. 단어학습 현재 구조
--------------------

관련 파일
- public/content/words/stage-1.json
- src/types/content.ts
- src/pages/WordStudyDayDetailPage.tsx

콘텐츠 단위
- Stage
  - Day
    - word
      - questions[]

현재 단어 1개당 기본 문제 패턴
1. word-to-meaning
   - 영어 단어를 보고 한국어 뜻을 고른다.
   - 학습 목적: 단어 인식, 뜻 매칭

2. meaning-to-word
   - 한국어 뜻을 보고 영어 단어를 고른다.
   - 학습 목적: 뜻에서 단어 회상

3. fill-blank
   - 예문의 빈칸에 들어갈 영어 단어를 고른다.
   - 학습 목적: 문맥 속 단어 사용 확인

단어학습 풀이 흐름
1. Day에 포함된 words를 불러온다.
2. 각 word의 questions를 순서대로 quizItems에 넣는다.
3. 사용자는 4지선다 선택지를 고른다.
4. 정답 확인 후 피드백을 본다.
5. 마지막 문제 후 결과 화면으로 이동한다.

Phase 17 UI 정책
- 단어학습 문제 화면은 현재 문제에 집중하는 단일 focus panel 안에 문제, 선택지, 피드백, 다음 버튼을 배치한다.
- 단어학습 JSON schema는 변경하지 않았다. word-to-meaning, meaning-to-word, fill-blank 타입을 그대로 사용한다.
- 저장, 코인, EXP, 정오답 처리, 결과 이동 정책은 UI 변경과 분리한다.

Day 흐름

4. 문장 맞추기 퀴즈

3. 대화 중 responseQuiz
----------------------

위치
- ConversationDialogueLine.responseQuiz
- learner 대사에만 붙인다.

역할
- 사용자가 장면 안에서 다음 말을 고르는 흐름이다.
- 정답을 고르면 자연스럽게 해당 learner 대사가 표시된다.
- 오답을 골라도 장면 진행은 막지 않고, 더 자연스러운 대사로 이어진다.

작성 원칙
- 정답 option text는 연결된 dialogue line의 textEn과 같아야 한다.
- promptKo는 앱 기능 설명이 아니라 상황 설명처럼 쓴다.
- 피해야 할 문장:
  - "이 대답이 내 대사로 이어집니다."
  - "내가 고른 답:"
  - "선택 후 다음 대화로 진행됩니다."


4. 실전회화 quiz
---------------

데이터 타입
- multiple-choice
- next-line-choice
- pattern-fill-blank
- blank-bubble-fill

현재 UI 렌더링
- multiple-choice, next-line-choice, pattern-fill-blank는 단어 풍선 문장 만들기 방식으로 렌더링한다.
- 사용자는 단어 토큰을 눌러 문장을 배열한다.
- 선택한 토큰은 다시 빼거나 좌우로 순서를 바꿀 수 있다.
- 정답 확인 후 다음 문제로 넘어간다.
- 마지막 quiz 후 결과 화면으로 바로 가지 않고, 핵심 표현/단어장 저장 흐름으로 이동한다.
- blank-bubble-fill은 기존 sentence-builder를 대체하지 않는 구현 완료 추가 패턴이다.
- blank-bubble-fill은 말풍선 안의 "{{blank}}" 빈칸에 option bubble 하나를 채우는 UX로 렌더링한다.
- Phase 17 기준 Stage 1 Day 1의 s1-d1-q3-next-line 1문항에 시범 적용되어 있다.
- TODO 후보: 선택 토큰을 touch-and-drag로 재정렬하는 기능은 검토만 했고 구현하지 않았다.

정답 문장 결정 규칙
- pattern-fill-blank:
  - templateEn의 "{{blank}}"에 correct option text를 넣은 문장
- blank-bubble-fill:
  - templateEn의 "{{blank}}"에 correct option text를 넣은 말풍선 문장
  - templateEn은 반드시 "{{blank}}" 토큰을 포함한다.
- multiple-choice:
  - promptEn 또는 promptKo에 backtick 문장(`...`)이 있으면 그 문장
  - 없으면 correct option text
- next-line-choice:
  - correct option text

blank-bubble-fill 예시
{
  "type": "blank-bubble-fill",
  "id": "s1-d1-q3-next-line",
  "expressionId": "s1-d1-k1",
  "templateEn": "Are you {{blank}} for dinner this Friday?",
  "promptKo": "초대 표현의 빈칸에 들어갈 자연스러운 단어를 고르세요.",
  "promptEn": "Complete the invitation bubble.",
  "options": [
    { "id": "a", "text": "free" },
    { "id": "b", "text": "late" },
    { "id": "c", "text": "closed" },
    { "id": "d", "text": "borrowed" }
  ],
  "correctOptionId": "a"
}


5. 문제 문장 톤
---------------

실전회화는 앱의 조작 설명보다 장면 몰입을 우선한다.

좋은 방향
- "직원이 원하는 시간을 물었습니다. 시간과 좌석 요청을 자연스럽게 말해 보세요."
- "친구가 주말에 영화를 볼 수도 있다고 했습니다. 자연스럽게 함께 가자고 제안하세요."
- "조금 어색해요. 자연스러운 순서는 아래와 같아요."

피해야 할 방향
- "정답입니다. 이 대답이 내 대사로 이어집니다."
- "오답입니다. 정답 대사가 내 대사로 이어집니다."
- "내가 고른 답:"
- "앱에서 다음 단계로 이동합니다."


6. 앞으로의 확장 방향
--------------------

- 단어학습은 현재 객관식 중심 구조를 유지한다.
- 실전회화는 responseQuiz와 quiz를 분리한다.
  - responseQuiz: 대화 중 즉흥 응답 선택
  - quiz: Day 핵심 표현을 문장으로 재조립하는 복습
- 새 Stage를 만들 때는 Day 1만 특별 취급하지 않고, 모든 Day가 같은 표준 수량과 흐름을 갖게 한다.
